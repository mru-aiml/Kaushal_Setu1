# KAUSHALSETU backend API (Phase 2A)

Zero-dependency Node.js HTTP server (`node:http`) + SQLite (`node:sqlite`) + `xlsx` for spreadsheet import/export. No Express, no ORM — one focused module per concern.

## Run

```bash
npm install
cp .env.example .env   # then fill in values (never commit .env)
npm start              # http://localhost:4000
npm test               # 13 end-to-end API tests (isolated temp database)
```

The frontend points at this server via `VITE_API_BASE_URL`.

## Layout

| File | Responsibility |
|---|---|
| `src/index.js` | Router, CORS, body limits, all endpoint wiring |
| `src/config.js` | Env loading/validation |
| `src/db.js` | SQLite open, schema/migrations |
| `src/seed.js` | Demonstration dataset (`is_demo=1`) |
| `src/auth.js` | scrypt passwords, token sessions, Google OAuth code flow |
| `src/rbac.js` | `requireAuth` / `requireRole` (server-side, every route) |
| `src/entities.js` | Dataset registry: fields, validation, ownership rules |
| `src/profiles.js` | Role profile schemas, validation, completion, persistence |
| `src/import.js` | CSV/XLSX parsing, import validation, resume PDF extraction |
| `src/ai.js` | LLM provider abstraction (OpenAI-compatible), strict JSON |
| `src/pdf.js` | Valid PDF-1.4 writer (text, tables, header/footer) |
| `src/reports.js` | Report catalog + generation (PDF/CSV/XLSX downloads) |
| `src/stats.js` | Dashboard aggregates from stored rows (demo-flagged) |

## Auth & RBAC

- Email/password with scrypt hashing; opaque Bearer sessions (30-day default).
- Google OAuth 2.0 authorization-code flow — requires `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET`; redirect URI `${BACKEND_URL}/api/auth/google/callback`. Without them, `/api/auth/google/url` returns 503 and the UI disables the button with an explanation.
- Role is stored on the `users` row and locked after onboarding (`role_locked` on re-assignment). The client-sent role is never trusted.
- Datasets: `gov` (government-managed aggregates, platform-readable) vs `own` (owner-scoped private rows; government has read-only oversight, never writes).
- Demo sessions (`POST /api/demo/session`) create sandboxed users (`demo_*`); their rows are excluded from shared aggregates/reports for real users.

## AI

`AI_PROVIDER=none` (default) → AI endpoints return 503 with a setup message; the UI shows it, never fake output.
`AI_PROVIDER=openai-compatible` + `AI_BASE_URL` + `AI_API_KEY` + `AI_MODEL` → real LLM calls (Groq, NVIDIA NIM, OpenRouter, Ollama, …) with strict JSON extraction/validation.

## Reports

`POST /api/reports/generate { type, filters, format }` builds from stored rows and writes a real file under `data/reports/`; `GET /api/reports/:id/download` streams it (owner-only). PDFs are generated by the built-in writer; CSV is RFC-4180; XLSX via the `xlsx` package. "Demonstration data" is stamped only when all rows used are seed rows.

## Data & limits

- SQLite file at `DATA_DIR/kaushalsetu.sqlite` (default `./data/`).
- Uploads: extension whitelist (csv/xlsx/xls/pdf), 5 MB default cap (`MAX_UPLOAD_BYTES`), PDF magic-byte check, import capped at 1000 rows/batch.
- Photos (500 KB) and resumes (2 MB PDF) stored in-DB as data URLs — move to object storage in Phase 2B.
